Method and limits
  • Compare the recorded pinned GoLSM revisions. Buffering, indexing, allocation, and maintenance work remain part of their measured behavior.
  • Flushes, queue waiting, and compaction can affect tails. Read p50 and throughput can move in different directions; inspect both measures.
  • Same Rust JSON codec, seed, 64 agents, latest K=10, Go C archive and included bridge copies. Final sync, full verification, and new-process reopen checks pass.
  • Foreground throughput includes generation, the oracle, and write read-backs. It excludes preload and final sync/full verification. Background work and changed table layout affect these results.
  • Three repetitions on a shared Azure VM, engine CPU 1 and observer CPU 0. Retained load-gate failures are flagged. These measurements remain preliminary.
  • This follow-up measures fast mode only. It provides no new durable-write, Kiban, or LMDB performance numbers. Existing three-engine results describe the old GoLSM revision.
