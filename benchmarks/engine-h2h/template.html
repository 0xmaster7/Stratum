What this comparison includes
  • 64 agents, seed 20261016, 200-byte text plus metadata, latest K=10. Bulk preload and two full base checks precede timed work; every write is read back, and final state is checked after a new-process reopen.
  • Durable: each write waits for persistence. Fast: no per-write sync; maintenance and final sync still happen. The three engines use different persistence paths.
  • GoLSM uses a Go C archive in the Rust driver. Its foreign-function call and result copies remain in the timer. The excluded echo/copy/free calibration has p50 .
  • Kiban is pinned to the version cited in the post, 361305a; GoLSM to b9a1c07; LMDB uses heed3 0.22.0 / lmdb-master3-sys 0.2.5. This does not measure newer Kiban read-path changes.
  • Shared Azure VM, 2 vCPUs, ~8 GiB RAM. Engine CPU 1; observer CPU 0. Different hardware and filesystem from the post. The 1M results remain preliminary with three trials. This is not a cold-cache or equal-memory test.
